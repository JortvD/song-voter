# Playlist Voter

A collaborative song ranking game. Voters pick between two songs in duels; every
pick updates the official shared score. Voters always see Your Ranking, while The
Standings stay hidden until the admin opens The Reveal.

**Current status: feature-complete.** Playlist Voter has invite-only accounts,
Spotify import with previews, duels, undo, Your Ranking, the official standings,
The Reveal, CSV export, a rich mission-control admin, rate limiting, backups and
security headers.

## Stack

- **Backend** — Rust, axum, sqlx, reqwest, tracing (plain-text structured logs)
- **Frontend** — React, TypeScript, Vite, Tailwind CSS
- **Database** — PostgreSQL 16
- **Packaging** — Docker Compose; the backend container serves the static frontend
- **TLS** — terminated by the host nginx (`vote.jortvd.nl` → `127.0.0.1:8765`)

## Quick start (Docker)

```bash
cp .env.example .env
# Set POSTGRES_PASSWORD, JWT_SECRET (openssl rand -hex 32),
# ADMIN_USERNAME, ADMIN_PASSWORD, and the Spotify settings below.
docker compose up -d --build
```

For playlist import, set `SPOTIFY_CLIENT_ID`, `SPOTIFY_CLIENT_SECRET` and
`SPOTIFY_REDIRECT_URI`, add the same redirect URI to the Spotify app dashboard,
then click **Connect** in the admin Playlist panel. Development Mode requires the
app owner to have Spotify Premium.

Then open <http://localhost:8765>. Sign in with the configured admin account,
create an invite code in the "Invites" panel, and register a voter account.

- `GET /healthz` — liveness, version and uptime (no DB access)
- `GET /readyz` — readiness, verifies PostgreSQL with `SELECT 1`

Logs are plain text on stdout, including a request id per request:

```bash
docker compose logs -f backend
```

## Auth & invites

- Registration is **invite-only**. Codes are 10 uppercase hex characters, single
  use, and generated by an admin.
- The invites panel can copy either the code or a ready-to-send link
  (`/?invite=CODE`). Opening the link switches the home sign-in card to Register
  and prefills the code.
- Passwords are hashed with Argon2; sessions are JWTs in an `HttpOnly`,
  `SameSite=Lax` cookie (`pv_session`, 7 days by default).
- The admin account is bootstrapped from `ADMIN_USERNAME` / `ADMIN_PASSWORD` on
  startup, so the first login never needs an invite. If the username already
  exists it is promoted to admin; the password is never overwritten.
- Every login, failed login, registration, logout and invite creation is written
  to the `auth_events` audit table and to the logs.

## Playlist import

- _Add_ `SPOTIFY_CLIENT_ID`, `SPOTIFY_CLIENT_SECRET` and
  `SPOTIFY_REDIRECT_URI` to `.env`. The redirect URI must exactly match the one
  registered in the Spotify app dashboard.
- Open the admin **Playlist** panel and click **Connect** to authorize the
  account that owns (or collaborates on) the playlist. The app stores the
  refresh token server-side and refreshes access tokens automatically.
- Since Spotify's **February 2026 API migration**, Development Mode apps can
  only read the items of playlists owned by, or collaborated on by, the
  authenticated user. Client credentials alone are no longer sufficient, even
  for public playlists. Development Mode also requires the app owner to have an
  active Spotify Premium subscription.
- Paste a playlist URL, a `spotify:playlist:…` URI, or a bare 22-character ID.
  Up to 2,000+ tracks are imported in pages of 50, with retry/backoff for
  Spotify rate limits and transient errors.
- Local files, podcast episodes, unavailable tracks and duplicate entries are
  skipped and counted in the import summary. Each track's 30-second Spotify
  preview URL is stored when available. When the Web API returns a null
  `preview_url` (common in Development Mode), the backend reads the preview MP3
  URL from the track's public Spotify embed page in the background.
- Importing a different playlist deactivates the previous one. Re-importing the
  same playlist refreshes metadata and upserts tracks — scores and pick counts
  are preserved. Tracks removed from Spotify are not deleted, so no history is
  lost.
- After deploying this version, existing tracks need their previews backfilled.
  Click **Fetch missing previews** in the Playlist panel, or re-import the
  playlist — both are safe and preserve picks.
- If no Spotify account is connected, the importer falls back to client
  credentials, which still works for Extended Quota apps reading public
  playlists.

### Playlist import returns 403

This is usually not a privacy problem anymore — it is Spotify's Development Mode
restriction. Check that you:

1. Added the exact redirect URI to the Spotify app, e.g.
   `https://vote.jortvd.nl/api/admin/spotify/callback`.
2. Set `SPOTIFY_REDIRECT_URI` in `.env` to that same value, then restarted the
   backend.
3. Clicked **Connect** in the Playlist panel and authorized with the account
   that owns or collaborates on the playlist.
4. Have an active Spotify Premium subscription on the app owner's account
   (required by Development Mode).

The connected account can read its own private playlists thanks to the
`playlist-read-private` scope, so the playlist no longer has to be public.

## Duel engine

`GET /api/matchup` returns two tracks plus progress (`compared_pairs`,
`total_tracks`). The duel engine works in three steps:

1. Take the 100 least-compared tracks (ties broken by least recently compared).
2. Among those, prefer the pair with the smallest score difference.
3. Exclude every pair this user has already been shown.

A pair is recorded in `seen_pairs` when it is served, so the same voter never sees
it twice — even if they abandon the duel. UUID ordering is normalised in the
table (`track_low < track_high`), while the left/right presentation is randomised
so position reveals nothing. When a small playlist runs out of unseen pairs, the
endpoint returns `409` with a friendly message.

The response exposes a public track shape only — no score, win or comparison
counts — so The Standings cannot be inferred from duels.

## Picking & scoring

`POST /api/vote` accepts `{ "track_a": "...", "track_b": "...", "winner": "..." }`.
A pick is only accepted for a duel that was served to that voter in the active
playlist, and only once per duel.

- Both tracks start at **1000**.
- `K = max(16, 40 − min(comparisons_a, comparisons_b) / 2)` — early picks move
  the standings, later picks settle them.
- Deltas are zero-sum: `delta_high = -delta_low`.
- Winner and loser ratings, `comparisons` and `wins` are updated in one
  transaction with both track rows locked in UUID order to avoid races.
- Every pick row stores the score before, the deltas, K, and comparison counts,
  forming the pick audit trail.
- The response does **not** expose ratings or deltas.

`POST /api/vote/undo` reverses the voter's most recent pick in the active playlist.
It subtracts the stored deltas, decrements comparisons/wins and deletes the pick.
The pair is kept in `seen_pairs`, so the duel screen can show it again and the
voter can immediately re-pick. Because undo subtracts deltas rather than restoring
snapshots, other voters' picks on the same tracks remain intact.

## The Duel screen

- `/duel` shows one **cassette card** holding both sides. On phones the sides are
  stacked; on desktop the cassette opens into a two-panel gatefold. A compact
  status strip keeps the round, duels, picks, coverage and `Undo` visible.
- Swipe the whole cassette **left for Side A** or **right for Side B**. The text
  block for each side is also a large pick button, and desktop panels add a big
  **Pick A / Pick B** button. Keyboard: `1`, `A` or `←` for Side A; `2`, `B` or
  `→` for Side B; `Z` to undo; `Space` to play/switch previews.
- Tap either album cover or the right-edge **Listen** transport key to play or
  pause the native **30-second Spotify preview**. Only one side plays at a time;
  each side resumes where it left off and a new duel resets both. A thin progress
  line and the cassette reels show playback.
- Spotify's embedded iframe shows a "Use the Spotify app" prompt that cannot be
  hidden from outside the iframe. The native preview player avoids it entirely;
  tracks without a preview show a **Spotify** link instead.
- On phones, the **Auto-preview** control sits below the card but outside the
  recent-duels height calculation. It is hidden at the top of the page and
  reveals itself after a scroll, so the duel card stays the lowest visible
  element and **Recent duels** keeps the extra space.
- Below the cassette, **Auto-preview** starts Side A, moves to Side B when A
  ends, and stops when B ends. The preference is remembered. Manually switching
  sides crossfades the previews over 0.2 seconds.
- Action sounds respect the footer **Sound** toggle: a tape-deck click and warm
  pick note (A and B are different notes), a tape-rewind undo, a transport-key
  auto-preview switch, a warm chime when the daily goal is completed, and a
  larger tape-deck fanfare at 7 / 30 / 100-day milestones.
- On a pick the cassette tilts, stamps **Picked**, plays a short stamp sound and
  lightly vibrates where supported. The next duel starts fetching immediately,
  with a short minimum stamp time, and the status strip updates live.
- `Undo` reverses the last pick and restores that duel so it can be re-picked.
- A compact **daily streak bar** under the status shows the current streak, today's
  `x / goal` pick progress and the last seven days. The home page shows the full
  streak card, an at-risk nudge when today's goal is still open, and a **Goal met**
  stamp once the daily goal is reached. Streaks are app-wide, use the browser's
  local day, and reset after a full missed day. Admins can change the daily goal
  from **Settings**.
- The space above the cassette shows **Recent duels**: a compact, picked-only
  history with both album covers and the winner checked. It fills the available
  space and fades out when more duels exist. On phones its height is calculated
  from the free space and then fixed, so scrolling or collapsing browser chrome
  cannot resize the panel.
- `/your-duels` is the full duel history for the active playlist. It includes
  duels you skipped, supports **All / Picked / No pick** filters, lets you tap a
  cover to preview the 30-second Spotify clip, and pages through the archive.
- `/your-ranking` replays only your picks to build Your Ranking. It lists songs
  you have actually compared, with wins, duels and your score. It is private to
  you; The Standings stay sealed until The Reveal. It uses the same compact search
  and collapsible artist/era/genre filters as The Standings, but keeps its
  personal ranking and has no podium.

## The Reveal & The Standings

- `/standings` is the **public standings page**; it needs no login. Until the
  admin opens The Reveal, the page shows a sealed cassette case with the playlist
  cover, name and pick count, but no standings data.
- The admin **The Reveal** panel opens or seals the standings. Picking continues
  after The Reveal, and the standings can be sealed again. The first time a voter
  sees the revealed page, a one-time **seal broken** moment appears.
- The revealed page is deliberately clean: a **top-three podium** followed by the
  **full hand-numbered tracklist**, which also includes the top three. Album art,
  wins, duels and score stay in the list, with infinite scroll and a visible
  **Load more** fallback.
- A compact search bar sits above the list, with an optional collapsible panel for
  **artist**, **era** and **genre** filters. Filtering keeps each song's official
  rank, hides the podium, and shows a match count so the results stay the focus.
  Signed-in voters can jump straight to **Your Ranking** from the standings header.
- `/stats` is the separate **stats page** (also in the nav). It holds the artist
  and album leaderboards, release timeline, genre explorer (when genres exist),
  liner notes and public top-5 leaderboards.
- Stats can be filtered by **artist**, **decade** and **genre**. The decade view
  is track-level: it uses the release date of each track, not the tape's import
  date. Artist and album stats respond to every filter.
- The liner notes show the most divisive and highest-rated albums, artists and
  decades, one-hit wonders, biggest upsets, coin-flip songs, the most
  argued-about duel, and a tape-at-a-glance summary. Cards are omitted until
  their minimum sample is met. `GET /api/chart/stories` exposes the same data and
  leaderboards.
- Decade stats come from Spotify release dates. Genres are Spotify artist genres
  mapped to a stable broad set; if Spotify rejects or omits the artist lookup, the
  backfill still completes, keeps all release/album metadata, and leaves genres
  blank instead of failing. Empty genre facets are hidden automatically.
- The standings are ordered by score, then wins, then title. The public page and
  the admin CSV use the same official order.
- **Download CSV** in the admin panel exports the official standings as
  `rank,title,artists,album,spotify_id,rating,comparisons,wins`, correctly
  quoting commas, quotes and newlines.
- `/your-ranking` is Your Ranking. `/standings` is the shared list.

## Scheduled seasons

- An admin can set a playlist and a future start time. The playlist name and
  cover are fetched immediately; the song list is fetched only when voting
  starts, so tracks added in the meantime are included.
- Before the start, users can sign in and browse. Duels, votes and undo are
  blocked with an “opens at …” message.
- **Start now** force-starts the scheduled playlist without waiting.
- Voting can be paused and resumed at any time, before or after The Reveal.
  Pausing blocks new votes and undo; existing picks and rankings are untouched.
- A reveal can be scheduled, with an optional “pause voting when the reveal
  opens” switch. A manual reveal or seal clears the pending reveal schedule.
- If Spotify fails at the scheduled start, the backend retries every minute and
  shows the last error in the admin playlist panel.
- A new playlist can be scheduled only when no loaded playlist is active. A
  scheduled (not started) playlist can be edited or cancelled safely.
- **Full reset** deletes every playlist, track, vote, duel, invite and other
  user. The Spotify connection is kept. Only the current admin account survives,
  and that admin stays logged in. There is no archive.

## Mission control

`/admin` is the mission-control dashboard, available to admin accounts. It uses
the same cream, cobalt and safety-orange visual language as the public site.

- **Overview** — a live read on the active playlist: total picks, picks today and
  over 7 days, active voters over 24 hours and 7 days, picks per voter, duels per
  voter, song coverage, uncompared tracks, preview gaps, the invite pipeline, a
  daily picks chart, an hourly picks chart, voter distribution, top tracks, top
  voters, recent picks and the Liner notes stories. Use the **Today / 7d / 14d /
  30d / 90d** range buttons to look back, then click any bar in the daily chart to
  see that day's picks and voters. The Liner notes section includes the story
  cards plus top-5 leaderboards for divisive/highest-rated albums, artists and
  decades, one-hit wonders, upsets, coin-flip songs and argued-about duels.
- **Playlist** — imports re-sync release dates, albums, artist links and broad
  genres, then queue a background metadata backfill. The panel shows release-year
  and genre coverage plus live track/artist progress, and the backfill can be
  re-run safely at any time.
- **Voters** — every account with picks, duels seen, join date and last activity.
  Sort by last active, most picks, most duels, newest or username; search by
  username, paginate, and export the full list as CSV. Expand a voter to rename
  them, reset their password, disable the account, revoke every session, clear
  their picks and duel history, or delete the account. Clearing or deleting
  rebuilds the affected playlists by replaying the remaining votes, so scores,
  win counts and the vote ledger stay correct, and clearing a voter's picks also
  resets their coverage so those duels can be served again. The last active admin cannot be deleted or disabled.
- **Standings** — the complete official standings with score, duels and wins even
  while The Standings are sealed; search, pagination and CSV export.
- **Playlist** — import or re-sync the Spotify playlist, connect or disconnect
  Spotify, inspect tracks and preview coverage, and fetch missing previews.
- **The Reveal** — open or seal the public standings, see the live/sealed state,
  and download the official CSV.
- **Invites** — generate invite codes, copy them, see open/used/expired status,
  and revoke unused codes.
- **Runtime** — backend version, environment, uptime and PostgreSQL readiness.
- **Danger zone** — reset all picks, duels and scores for the active playlist
  (and seal The Standings), or remove the playlist entirely to return to the
  empty state. Both require typed confirmation; voters, invites and the Spotify
  connection are kept.

## Security, operations & backups

- **Production secret checks** — in `APP_ENV=production` the backend refuses
  to start with an empty/ephemeral `JWT_SECRET`, the example JWT secret, an
  example or weak `ADMIN_PASSWORD`, or a `DATABASE_URL` that still contains the
  example Postgres password. Generate real values in `.env` before deploying.
- **Rate limiting** — login attempts are limited per client IP per minute and
  registrations per client IP per hour. Both are configurable with
  `AUTH_LOGIN_RATE_LIMIT` / `AUTH_REGISTER_RATE_LIMIT`.
- **Security headers** — responses include a strict CSP, `X-Frame-Options:
  DENY`, `X-Content-Type-Options: nosniff`, a referrer policy and a permissions
  policy. API responses are marked `Cache-Control: no-store`.
- **Sessions** — JWT in an HttpOnly, SameSite=Lax cookie; Secure in production.
  Expired/revoked sessions are detected by the frontend and drop you back to the
  sign-in screen.
- **Request timeout** — HTTP requests are capped at 180 seconds. Large playlist
  imports can involve dozens of Spotify pages and rate-limit backoff; the
  database statement timeout still protects individual queries.
- **Backups** — run `./scripts/backup.sh` (writes `backups/playlist-voter-*.sql.gz`,
  keeps 14 days). Schedule it with cron, for example:
  ```
  15 3 * * * cd /srv/playlist-voter && ./scripts/backup.sh >> backups/cron.log 2>&1
  ```
  Restore with `./scripts/restore.sh backups/<file>.sql.gz`. Backups contain
  password hashes and Spotify tokens — keep them private.
- **Nginx** — use `deploy/nginx/vote.jortvd.nl.conf`. It listens on HTTP port
  80 and proxies to the compose host port 8765; run `certbot --nginx` afterwards
  and it will add HTTPS + the redirect. Its access log uses `$uri` instead of
  `$request`, so Spotify OAuth codes in callback query strings are not written
  to disk. Proxy all paths so SPA routes work:
  ```nginx
  location / {
      proxy_pass http://127.0.0.1:8765;
      proxy_set_header Host $host;
      proxy_set_header X-Real-IP $remote_addr;
      proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
      proxy_set_header X-Forwarded-Proto $scheme;
      proxy_read_timeout 195s;
  }
  ```
  `X-Forwarded-For` is used for audit logging and rate limiting; keep it set.

## Local development

Backend (needs a reachable PostgreSQL; `docker compose up -d db` starts one):

```bash
cd backend
export DATABASE_URL=postgres://ulltop2000:change-me@localhost:5432/ulltop2000
export JWT_SECRET=$(openssl rand -hex 32)
export ADMIN_USERNAME=admin ADMIN_PASSWORD=local-dev-only
export COOKIE_SECURE=false   # plain HTTP on localhost
cargo run
```

To reach the compose database from the host, temporarily publish its port in
`compose.yaml` (`ports: ["127.0.0.1:5432:5432"]`), or run the backend inside
compose as well.

Frontend:

```bash
cd frontend
npm install
npm run dev        # http://localhost:5173, proxies /api, /healthz, /readyz to :8080

# If the backend runs through Docker Compose on host port 8765:
VITE_API_PROXY=http://127.0.0.1:8765 npm run dev
```
